## 2. 判据：三问

一个模块或改动是否属于引擎，看三个问题——答"是"就说明它知道业务：

1. 它知道具体名词吗？（金币、订单、渠道、商品）
2. 它知道具体策略或数值吗？（汇率、保留期、状态机分支、渠道 ACK 规则）
3. 换一个游戏，这段代码需要改吗？

三条都否 → 引擎原语。任一是 → 领域包或游戏层。

**要区分的两件事**：引擎不定义"充值给多少金币"（那是业务），但必须保证"订单不会因为切主而消失"
（那是持久化语义）。前者是策略，后者是引擎欠的债。最近几轮修的全部是后者。

## 5. 边界规则（候选，待认可后写进 `AGENTS.md`）

1. **引擎可以拥有"领域中立机制"，不能拥有"领域策略"。** `service_op_id` 的推导规则是机制；
   "什么算一次有效支付"是策略。
2. **领域包必须可删除。** 删掉 `charge_*` / `pay_*` 后，`make build` 与引擎测试仍然通过。
   做不到就说明耦合进了引擎。
3. **业务数值不许进 `lualib/skyext/`。** 汇率、商品、奖励、活动时间一律在游戏层配置。
   当前这条是守住的（§1 已核对），要写下来避免以后破例。
